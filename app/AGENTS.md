# AGENTS.md

Інструкції для агентів, що працюють у цьому репозиторії.

## Мета проєкту
У проєкті є наявні сторінки та окремі завдання. Для поточного великого розділу `drop` дотримуємося спеціальних обов'язкових правил нижче. Правила для `drop` мають перевагу над загальними або застарілими вказівками цього файла, якщо вони суперечать одна одній. Не змінювати інші сторінки чи спільні наявні ресурси без потреби, прямо пов'язаної із завданням.

Розробка якісної, валідної та адаптивної верстки на:

- `HTML5`
- `SCSS`
- `JavaScript`
- `jQuery` (дозволено, коли це виправдано)

## Обов'язкові правила

0. Врістаємо за принципом «Mobile first». 
1. Верстати за методологією **BEM**.
2. Писати стилі тільки в **SCSS** використовувати міксини. .
3. Для layout-рішень використовувати **Flex** (не Grid), якщо користувач не попросив інакше.
4. Дотримуватися **DRY** у всій верстці: HTML, SCSS і JavaScript (не дублювати структури, стилі та логіку без потреби).
5. Використовувати семантичний HTML.
6. Забезпечувати валідність розмітки та коректну адаптивність.
7. Не ускладнювати селектори і не зловживати вкладеністю в SCSS.
8. Не видаляти вже зверстані блоки/секції без прямого запиту користувача.
9. Для бібліотек, API, фреймворків і практик завжди спиратися на **Context7** (не вигадувати best practices з пам'яті).
10. Усі зображення/іконки з Figma зберігати локально в проєкті (наприклад `images/assets/`) і використовувати лише локальні шляхи.
11. Після будь-яких змін у `SCSS` обов'язково пересобирати фінальний `CSS` перед завершенням задачі.
12. в тегах p, h, span, не повинно бути класів. Ми на них впливаємо через класс батьківського елементу. div>p 
13. не стирати вже зверстані секції , якщо на це не вказав замовник прямо.
14. Всі фото не повинні посилатися на макет фігми, а бути скопійовані до нас в проєкт.
15. css, який підключається до сторінки, повинен бути мінімізований .min.css
16. Фотографії із Figma  JPEG PNG, які ми тягнемо, бажано тягнути в X2.
17. В планшетній версії ми показуємо мобільну версію, тобто не виходимо за рамки розміру 768. Ми обмежуємо весь розмір сторінки такою шириною на всій планшетній версії.

## Обов'язкові правила для розділу `drop`

Ці правила діють для всіх робіт над розділом `drop` і є обов'язковими.

1. Наявні JavaScript- та SCSS-файли не редагувати. Їх можна підключати або використовувати без зміни вмісту. Усі нові стилі для `drop` писати в окремому SCSS-файлі та його власних partials; не додавати стилі розділу до існуючих SCSS.
2. Розмітку та стилі розділу писати за методологією **BEM** відповідно до правил цього файла.
3. Розділяти стилі на SCSS partials за компонентами та призначенням. Для повторно використовуваної HTML-розмітки, зокрема хедера й футера, використовувати спільні HTML partials, щоб не переверстувати ці компоненти на кожній сторінці.
4. Виносити повторювані HTML-компоненти розділу в partials. Не створювати окремий partial для одноразового фрагмента без потреби.
5. Використовувати семантичні HTML-елементи та забезпечувати валідність і адаптивність розмітки.
6. Для компонування надавати перевагу **Flexbox**. Використовувати CSS Grid лише у виняткових випадках, коли компонування нераціонально реалізувати Flexbox.
7. Перед завершенням робіт зібрати повну сторінку розділу в HTML-файл у каталозі `build`. У проєкті вже є команда `npm run build`; за потреби розширити наявну збірку для нових файлів, не створюючи дубльовану команду.
8. Усі файли розділу зберігати в підпапці `Drop` у відповідному стандартному каталозі: SCSS — `app/scss/Drop/`, зібраний CSS — `app/css/Drop/`, JavaScript — `app/js/Drop/`. Нові partials і файли збірки мають зберігати цю структуру, наскільки це підтримує наявна збірка.

## Стандарти BEM

- Формат:
  - Block: `.block`
  - Element: `.block__element`
  - Modifier: `.block--modifier` або `.block__element--modifier`
- Не використовувати id як основу для стилізації.
- Не будувати архітектуру на тегових селекторах.

## Стандарти SCSS

- Організовувати стилі модульно (base/layout/components/pages).
- Використовувати змінні для кольорів, відступів, типографіки, брейкпоінтів.
- Виносити повторювані патерни в міксини або placeholder'и.
- Зберігати стилі компонента поруч із його BEM-структурою.
- SCSS є джерелом правди; фінальний CSS має бути згенерований із SCSS.

## Стандарти Layout

- Базовий інструмент для розкладки: **Flex**.
- Не використовувати CSS Grid без прямого запиту користувача.

## Стандарти JavaScript

- Перевага за нативним JS.
- jQuery використовувати точково, тільки коли це доречно.
- Мінімізувати залежність від DOM-структури; краще працювати через BEM/data-атрибути.
- Не додавати зайвих бібліотек без потреби.

## Definition of Done (DoD)

Завдання вважається виконаним, якщо:

- HTML валідний та семантичний;
- верстка адаптивна;
- класи відповідають BEM;
- layout побудований на Flex (якщо немає іншої вимоги користувача);
- стилі SCSS структуровані, без дублювань;
- усі ассети збережені в репозиторії локально (без зовнішніх Figma URL у розмітці/стилях);
- JS-поведінка працює стабільно;
- рішення перевірене за актуальною документацією через Context7.
